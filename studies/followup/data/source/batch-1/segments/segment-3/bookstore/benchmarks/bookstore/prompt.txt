An online bookstore starts sending some customers two order-confirmation emails after Monday's mobile-app release. The team suspects the new app, the mail provider, or an older server fault. Orders themselves are not duplicated.

The investigation finds:
- The server has not changed for three months. The new app shortened its request timeout from eight seconds to two, then retries with the same order ID.
- The mail provider's records show two separate send requests for each duplicated email, rather than one request delivered twice.
- The old app can reproduce the problem when given the shorter timeout. Giving the new app the old timeout makes duplicates much rarer.
- Replaying one request, or two sequential requests for the same order, sends one email. Two overlapping requests for the same order sometimes send two emails, with either app version.
- In those overlapping cases, both server requests read "email_sent = false" before either finishes. Each sends the email and only then records "email_sent = true".
